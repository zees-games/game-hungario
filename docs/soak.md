# Bot soak

`./game.sh soak [mode] [minutes]` runs `tools/soak.tscn`: eight `HungryBot`s play rounds back to back in one mode (`classic`, `frenzy`, `gauntlet`, `warrens`, `reef`, `shallows`) on a real `HungryWorld`, driven by dot-bot's `DotBotSoak` with dot-spawn's `DotSpawnWatch` for stuck verdicts. The report is `.godot/test-logs/soak-<mode>.json` and one `SOAK {...}` line; the exit code is 1 on failure. Kills are not a signal (eating each other is the game working), there is no navigation query for a monster so off-nav and unreachable are off, and a bot between rounds or dead has no goal. The mover position is the rider piece's head.

First run, 2026-10-22, 1 simulated minute per mode, 8 bots, seed 1: classic passes; frenzy, gauntlet, warrens, reef and shallows fail, all `stuck` (a bot within one radius for over 10 s): frenzy 11.7 s, reef 20.3 s, gauntlet 25.1 s, shallows 40.0 s (all 8 bots), warrens 46.9 s. Tick cost is fine (p95 1.7 to 2.7 ms at 60 Hz, worst tick 7.8 ms) and object and memory growth are within limits. Not yet known whether these are bots parked against walls and rocks, bots content to sit on a full patch of food (a monster that is eating is not travelling, so the harness's stuck rule may be too strict for this genre), or a real steering trap in the layouts; filed on the nightly board rather than fixed.
